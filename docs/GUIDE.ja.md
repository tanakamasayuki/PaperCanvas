# 入門ガイド

> English: [GUIDE.md](GUIDE.md)

PaperCanvas を使い始めるときに一度読むもの。API の一覧は [API.ja.md](API.ja.md)。

## 1. 最初に決めること — 印字可能幅

**この 1 つが他の何より効きます。** 小さすぎれば紙が無駄になり、大きすぎれば右端がプリンター側で切られます。**切られたことはどこからも通知されません。**

```cpp
PaperCanvas::Receipt r(384);   // 印字可能幅（ドット数）
```

この値は**プリンターの仕様書にドット数で書かれている**のが普通です。紙幅より印字可能幅のほうが狭いためで、58mm 紙・203dpi を素直に換算すると 463 ドットになりますが、**実際の 58mm プリンターはほぼ 384 ドット**です。残りは余白。

| 紙幅 | 典型的な印字可能幅 |
| --- | --- |
| 58mm | 384 ドット |
| 80mm | 576 ドット |

**メーカーが出しているドット数を使ってください。** `mmToPx()` は、物理寸法しか分からないとき（ラベル用紙のサイズなど）のためのものです。

```cpp
constexpr uint16_t W = PaperCanvas::mmToPx(50.0f, 203);   // ラベル 50mm → 400px
```

[examples/PrinterWidths](../examples/PrinterWidths/) が幅ごとの見え方を並べます。

## 2. レシートとラベルは別物です

混ぜないでください。使えるメソッドが違うので、間違えるとコンパイルが通りません。

| | Receipt | Label |
| --- | --- | --- |
| 高さ | **内容で決まる** | 最初に決める |
| 配置 | 上から積む | 矩形で置く |
| 自動折り返し | **既定 ON** | **既定 OFF** |
| はみ出すと | 縦に伸びる | クリップされる |

折り返しの既定が違うのは、レシートは下に伸びるので折り返しても安全で、ラベルは固定矩形なので折り返すと溢れるからです。

## 3. フォントの選び方

PaperCanvas はフォントを持ちません。LovyanGFX の `IFont*` を渡します。

```cpp
r.setFont(&fonts::efontJA_16);   // 日本語
r.setFont(&fonts::Font2);        // ラテンのみ、軽い
```

**203dpi では 1mm ≈ 8 ドット**です。感熱プリンターの実際のドットは仕様上の大きさより滲むので、画面での見た目より一回り大きめが読みやすくなります。

> 下の表の実寸は計算値（203dpi = 8 ドット/mm）で、**滲みの程度は実機で測っていません**。目安として読んでください。確認手順は [MANUAL_TEST.ja.md](MANUAL_TEST.ja.md) T2。

| フォント高 | 203dpi での実寸 | 用途 |
| --- | --- | --- |
| 12px | 約 1.5mm | 注記・但し書き。**小さすぎることが多い** |
| 16px | 約 2mm | 明細・本文。**まずここから** |
| 24px | 約 3mm | 見出し、合計金額 |
| 32px 以上 | 4mm 以上 | 大きく見せたい数字 |

日本語は `efontJA_*` か `lgfxJapanGothic_*` / `lgfxJapanMincho_*`。**フラッシュを大きく食う**ので、必要なサイズだけ使ってください。

`setTextSize(2)` で倍率をかけることもできますが、**ビットマップフォントの整数倍拡大はギザギザになります。** その大きさのフォントがあるならそちらを使うほうがきれいです。

## 4. 「品名 … 金額」を空白で作らないでください

**空白パディングは成立しません。** プロポーショナルフォントでは空白の幅が揃わず、等幅でも必要な空白数を数えることになります（全角・半角が混ざればなおさら）。

```cpp
r.addRow("コーヒー", "480");            // 品名は左、金額は右端
r.addRow("サンドイッチ", "620");         // 名前の長さが違っても金額は揃う
```

3 列も書けます。

```cpp
r.addRow("コーヒー", "x2", "960");
```

列幅を明示したいときは:

```cpp
const PaperCanvas::Column cols[] = {
  PaperCanvas::Column::percent(55, PaperCanvas::Align::Left, '.'),   // リーダーはドット
  PaperCanvas::Column::percent(15, PaperCanvas::Align::Center),
  PaperCanvas::Column::rest(       PaperCanvas::Align::Right),
};
r.setColumns(cols, 3);
```

**列幅は行ごとに解決され、文字の長さに左右されません。** だから何行並べても縦に揃います。

セルが列に収まらないときは、その列の中で折り返す（`wrap` が真）かクリップされるかで、**他の列は動きません**。

## 5. 設定は「以後」に効きます

```cpp
r.setTextSize(1);
r.addText("小さい");     // 1 倍
r.setTextSize(2);
r.addText("大きい");     // 2 倍。上の行は変わらない
```

要素は追加された時点の設定を自分の中に持ちます。だから `height()` を積みながら問えます。

```cpp
uint16_t h = r.height();   // いつでも。build() の前でもよい
```

## 6. 画像

8bit グレー（1 バイト 1 画素、0 が黒）か、PaperCanvas と同じ 1bpp の `Bitmap` を渡せます。

```cpp
r.addImage(gray8, w, h, {.fit = PaperCanvas::Fit::Contain});
```

**写真を刷るならディザを指定してください。**

```cpp
r.addImage(photo, w, h, {.mono = PaperCanvas::Mono::Bayer4x4});
```

| 方式 | 向いているもの |
| --- | --- |
| `Threshold`（既定） | ロゴ、線画、すでに白黒のもの |
| `Bayer4x4` | 写真。中間調が出る |
| `Bayer8x8` | 写真。より滑らかだが網目が粗い |

> `Bayer4x4` と `Bayer8x8` の優劣は**画面で見た評価**です。感熱では滲みで網目が埋まるため、紙の上では逆転する可能性があります（[MANUAL_TEST.ja.md](MANUAL_TEST.ja.md) T3）。

**画像データは利用者が保持し続けてください。** 文字列と違い、画像はコピーされません（大きなロゴを RAM に複製するのは割に合わないため）。`build()` まで生かしておく必要があります。

## 7. バーコード

```cpp
#include <PaperCanvasBarcode.h>
```

倍率の整数化・クワイエットゾーン・ガードバー延長はライブラリがやります。**確認すべきは戻り値だけ**です。

```cpp
if (r.addBarcode(bc, {.barHeight = 60}) == 0) {
  // 倍率1でも収まらなかった。何も描いていない
}
```

**読めない大きさなら描きません。** 刷ってしまうと、スキャンするまで誰も気づけないからです。事前に確認することもできます。

> 既定（`moduleWidth = 0`）は**収まる最大の整数倍**を選ぶので、幅が足りなければ 1 モジュール 1 ドットになります。**1 ドットで実スキャナが読めるかは未確認**です（[MANUAL_TEST.ja.md](MANUAL_TEST.ja.md) T4）。確実を期すなら `moduleWidth` を 2 以上で明示してください。

```cpp
auto l = PaperCanvas::barcodeLayout(bc, opt, r.width());
if (!l.fits) { /* 幅が足りない */ }
```

## 8. 長尺レシート

明細が長いとページが大きくなります。384px × 4000px で 192KB。

```cpp
r.setMemoryLimit(16 * 1024);
r.stream([](const PaperCanvas::Bitmap& band, uint16_t y, void*) {
  sendBand(band.data, band.rowBytes, y);
});
```

`stream()` はページを保持しません。**作業メモリはレシートの長さではなくタイル予算で決まります。** 帯は `build()` が作るのと同じバイト列を、上から順に渡します。

PSRAM があるなら `setUsePsram(true)` でタイルをそちらに置けます（遅くなりますが分割数を減らせます）。

## 9. 警告は生成を止めません

```cpp
if (r.warnings() & PaperCanvas::Warning_TextClipped) { /* 文字が切れた */ }
```

| 警告 | 意味 |
| --- | --- |
| `TextClipped` | 収まらず文字が切れた |
| `TextWrapped` | 折り返しが発生した |
| `ImageScaled` | 画像が**縮小**された（拡大は報告しません） |
| `ImageClipped` | 画像が矩形からはみ出した |
| `OutOfBounds` | 要素がキャンバス外に置かれた |
| `BarcodeTooSmall` | バーコードを**描かなかった** |

**指定ミス 1 つで印刷全体が失敗するほうが実運用では困る**ので、警告を立てて紙は出します。例外はバーコードだけです。

## 10. 印刷結果が思ったとおりにならないとき

上から順に確認してください。

### 右端が切れる

**印字可能幅が実際より大きい。** §1。仕様書のドット数を確認してください。紙幅から換算した値だと必ず大きすぎます。

### 文字が切れる、途中で消える

`warnings()` に `TextClipped` が立っていませんか。

- レシートなら `setWrap(true)`（既定 ON）で折り返す
- ラベルなら矩形を広げるか、フォントを小さくする
- 列に入らないなら列幅の指定を見直す（§4）

### 文字が小さくて読めない

§3 の表。**画面で見た印象より一回り大きめ**が要ります。感熱印刷はドットが滲みます。

### 画像が真っ黒／真っ白になる

`Mono::Threshold`（既定）は 128 で切ります。写真なら `Bayer4x4` を指定してください（§6）。

ロゴが潰れる場合は、元画像がアンチエイリアス付きの可能性があります。閾値を上下させるか、1bpp で用意し直すのが確実です。

### バーコードが読めない

1. **描かれていますか。** `addBarcode()` が 0 を返していれば描いていません（§7）
2. **クワイエットゾーンを潰していませんか。** `quietZone = true`（既定）のままにしてください。ライブラリが確保した余白の上に何か置くと無効になります
3. **紙送り方向に対してバーが細すぎませんか。** `moduleWidth` を明示して太くしてみてください
4. **印字が薄くありませんか。** プリンターの濃度設定は PaperCanvas の外です

### 分割数を変えたら結果が変わった

**これは不具合です。** 出力はメモリ上限に依存しないことが保証されています。再現手順を添えて報告してください。

### `build()` が false を返す

- バッファが `bufferSize()` 未満
- レシートに要素が 1 つも無い（高さ 0）
- キャンバスの幅か高さが 0
- タイルバッファを確保できない

**失敗したときは何も書き込みません。** バッファを直してもう一度呼べます。ページを組み直す必要はありません。
